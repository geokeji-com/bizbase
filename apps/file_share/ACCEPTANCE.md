# 文件分享 App 本地验收

## 2026-11-21 同事自助安装与终端禁用

- 匿名访问 `/file-share-setup` 可看到安装、移山 ID 登录、首次绑定和管理入口。Chrome 已在本机预览站渲染页面并下载资产。隔离站点的三个全新用户目录从本站下载清单与客户端，核对 SHA-256，安装 CLI 和技能，并重复安装验证更新。删除临时下载件后，已安装的 CLI 仍能登录并返回正确员工身份。
- 同一员工分别授权两台终端。管理员从终端授权记录禁用其中一台，再次执行同一禁用操作也成功。被禁用终端立即无法运行 `whoami`，另一台终端和另一名员工的终端仍能使用。普通员工列表只返回本人的授权，访客和其他员工的禁用请求均被拒绝。
- 在已安装移山 ID 的实验站写入合成的、仍有效的已验证身份会话，核对 CLI 可用后，管理员通过原生单据接口停用对应移山 ID 绑定。该终端的下一次请求即被拒绝。
- 同事的原生移山 ID 扫码与公网 TLS 需要在具备真实员工身份和正式域名的环境验收。隔离测试使用合成员工账号，通过 HTTP 会话完成终端授权确认。[自动验收用例](../../deploy/local-pg/share-qa/check_onboarding.py)

## 2026-11-21 员工委托 CLI 与 Agent（一次性 PostgreSQL 16 站点）

运行 `rtk proxy bash deploy/local-pg/share-qa/run.sh`。Compose 创建独立站点和内部网络，执行原有分享回归以及[员工 CLI 端到端用例](../../deploy/local-pg/share-qa/check_cli.py)。

| 路径 | 实测结果 |
| --- | --- |
| 两名普通员工的 CLI 登录 | 两人各自通过原生密码登录。HTTP 客户端读取授权页显示的 challenge 和 CSRF，确认后真实 CLI 完成令牌交换，`whoami` 返回相应员工。 |
| 报告与权限 | 一人上传私有 HTML 草稿，另一人的 CLI 列表不含该报告，查询和关闭均被拒绝。Desk 会话读取原生单据也遵循所有者范围，文件分享专用令牌单独访问原生单据被拒绝。 |
| 版本和域名 | 两个域名固定到 V1，再上传 ZIP 草稿。单独将第一个域名切到 V2、回退 V1、关闭，另一个域名全程交付 V1。检查了收件人实际收到的报告内容。|
| 重试与追溯 | 重复相同请求 ID 的上传和发布得到相同回执。两次上传、四次发布/切版和一次关闭对应七条成功操作记录。读回员工、操作、请求 ID、版本、域名和时间。 |
| 查看范围与撤权 | 验证公开、内部员工、指定人员和密码入口。保留原授权切版后，内部/指定入口对匿名用户仍需登录，密码入口保留已验证状态。关闭入口后不能用 `--keep-access` 重新开放。CLI 退出或退出原浏览器会话后，原凭证均被拒绝。 |
| Agent 按 skill 调用 | Agent 阅读[文件分享 skill](../../skills/bizbase-share/SKILL.md)，在普通员工已委托的隔离站点实际执行 `whoami`、`domains`、`upload`、`publish`、`show`、`close`、`show`。合成报告 `3F2fhL3Jz2` 的内部入口从 V1 已启用变为 `enabled=false`，关闭后返回 `url=null`。 |

本次使用合成员工和报告，在站内回环 HTTP 服务运行实际 CLI 与 Frappe。浏览器同意操作由持有员工会话的 HTTP 客户端模拟。真实移山 ID 扫码、图形界面点击、生产 TLS 和公网发布需在相应环境单独验收。

## 2026-11-20：多域名发布（隔离环境，尚未上线）

- 在 Frappe 镜像内运行 37 项 Python 测试，覆盖归档、路径、入口权限、凭证、版本、迁移和旧链接；Desk 菜单与路由的 4 项 Node 测试通过。
- [一次性 PostgreSQL 验收](../../deploy/local-pg/share-qa/)创建独立站点，安装 ERPNext、文件分享并执行 `migrate`。用合成记录模拟旧链接和无标题日志，实际执行发布入口迁移两次，确认只建立一个入口、保留原盐值、回填标题、导入原生侧栏。测试曾发现 PostgreSQL 不接受原回填 SQL，改为显式关联更新后整套验收通过。
- 从真实 Frappe HTTP 应用按三个不同 Host 读取同一报告：公司访问 V4，渠道 A 输错密码被拒、输入正确密码后访问 V2，未开放的渠道 B 外壳和资源均返回 404。只将 A 切换到 V4 后，原密码状态可继续用、旧资源凭证失效；关闭 A 后，A 的旧入口和内容返回 404，公司仍能访问。核验了实际日志中的标题、域名和交付版本。
- 这不是生产代理或浏览器验收：未使用公网 DNS、TLS、渠道身份登录或共享 8080 开发站。真实域名接入后需核对 Nginx、浏览器沙箱 Cookie、登录及原生菜单交互。

## 历史验收：仅应用显示名与对外链接改名（旧安装名 `static_share`）

在本地 `frontend` 站点通过 Frappe 16.56.0 与 Nginx 实测。`/file-share` 返回 302 到 `/desk/static-share`。未登录访问原列表或表单会转到登录页，并带回原 Desk 地址。

- `/file-share/<ID>` 与 `/s/<ID>` 的公开外壳、HTML 入口、相对 CSS、JS 和 PNG 均返回 200。两套路径上资源响应的 CSP 限定到本次资源目录，代理均屏蔽资源响应的 `Set-Cookie`。切换前签发的旧资源地址在有效期内仍返回 200。
- 临时密码分享在两个入口上均验证了错误密码 401、正确密码 303、回跳保留 `?v=1`、访客只读当前版本以及缺少资源 Cookie 返回 403。无站点回归另行覆盖作者预览历史版本及非作者只能看当前版本，共 24 项通过。
- 本地原有 3 条默认分享地址均完成迁移。事务内重复执行迁移，核对了自定义 URL、版本、上传、访问盐值和修改时间。另用合成桌面图标和已保存布局核对了标签与入口更新、隐藏状态、文件夹及其他应用条目。

| 已验证的操作 | 观察到的结果 |
| --- | --- |
