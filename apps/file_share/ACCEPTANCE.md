# 文件分享 App 本地验收

## 2026-11-20：多域名发布（隔离环境，尚未上线）

- 在 Frappe 镜像内运行 37 项 Python 测试，覆盖归档、路径、入口权限、凭证、版本、迁移和旧链接；Desk 菜单与路由的 4 项 Node 测试通过。
- [一次性 PostgreSQL 验收](../../deploy/local-pg/share-qa/)创建独立站点，安装 ERPNext、文件分享并执行 `migrate`。用合成记录模拟旧链接和无标题日志，实际执行发布入口迁移两次，确认只建立一个入口、保留原盐值、回填标题、导入原生侧栏。测试曾发现 PostgreSQL 不接受原回填 SQL，改为显式关联更新后整套验收通过。
- 从真实 Frappe HTTP 应用按三个不同 Host 读取同一报告：公司访问 V4，渠道 A 输错密码被拒、输入正确密码后访问 V2，未开放的渠道 B 外壳和资源均返回 404。只将 A 切换到 V4 后，原密码状态可继续用、旧资源凭证失效；关闭 A 后，A 的旧入口和内容返回 404，公司仍能访问。核验了实际日志中的标题、域名和交付版本。
- 这不是生产代理或浏览器验收：未使用公网 DNS、TLS、渠道身份登录或共享 8080 开发站。真实域名接入后需核对 Nginx、浏览器沙箱 Cookie、登录及原生菜单交互。

## 技术名统一后的回归

`file_share.tests.test_core` 与 `file_share.tests.test_policy` 在本地 Frappe 隔离容器共 26 项通过。包括应用卡片与管理跳转使用 `/desk/file-share`、改名前的密码令牌仍有效、原私有资源授权保持不变。另在本地 PostgreSQL 16 的 8080 入口通过 Chrome 检查：卡片落在 `File Share` 列表 `/desk/file-share`，旧 `/desk/static-share/<ID>` 书签落在 `/desk/file-share/<ID>` 并加载同一份临时停用记录。旧列表书签和带查询参数的深链均返回新地址。未在生产执行这次迁移。

## 历史验收：仅应用显示名与对外链接改名（旧安装名 `static_share`）

在本地 `frontend` 站点通过 Frappe 16.56.0 与 Nginx 实测。`/file-share` 返回 302 到 `/desk/static-share`。未登录访问原列表或表单会转到登录页，并带回原 Desk 地址。

- `/file-share/<ID>` 与 `/s/<ID>` 的公开外壳、HTML 入口、相对 CSS、JS 和 PNG 均返回 200。两套路径上资源响应的 CSP 限定到本次资源目录，代理均屏蔽资源响应的 `Set-Cookie`。切换前签发的旧资源地址在有效期内仍返回 200。
- 临时密码分享在两个入口上均验证了错误密码 401、正确密码 303、回跳保留 `?v=1`、访客只读当前版本以及缺少资源 Cookie 返回 403。无站点回归另行覆盖作者预览历史版本及非作者只能看当前版本，共 24 项通过。
- 本地原有 3 条默认分享地址均完成迁移。事务内重复执行迁移，核对了自定义 URL、版本、上传、访问盐值和修改时间。另用合成桌面图标和已保存布局核对了标签与入口更新、隐藏状态、文件夹及其他应用条目。

## 更早的验收记录

环境为 Compose 项目 `bizbase`、站点 `frontend`、浏览器访问 `http://127.0.0.1:8080`。使用合成报告和本地测试账号，员工条件为启用的 Desk 用户关联状态为 `Active` 的 Employee。正式身份提供方的登录联调另行验证。

| 已验证的操作 | 观察到的结果 |
| --- | --- |
| 从 8080 Desk 以普通在职账号新建分享、上传私有 HTML、保存 | 成功创建第 1 版，浏览器可打开报告 |
| 点击复制链接 | 系统剪贴板包含当前站点完整的 `/s/<10位ID>` 外壳链接 |
| 上传新版 ZIP，打开相对路径资源并回退 | 浏览器加载包内脚本、样式和图片，回退后从原分享链接看到旧版 |
| 内部可见、指定人员、指定角色 | 在职员工按范围查看。移除成员或撤销角色后，原浏览器重取旧内容返回 403 |
| 指定员工退出登录 | 同一浏览器重取已打开的私有内容由 200 变为 403；打开外壳返回 302，跳转登录 |
| 匿名密码访问 | 错误密码返回 401，正确密码返回 303 并加载 ZIP。改密后旧凭据失效 |
| 完全公开 | 匿名浏览器打开示例，外壳与内容均返回 200 |
| 停用与原始附件 | 停用后旧入口无法重新取回报告，未经授权的查看者无法直接下载私有原件 |
| 运行令牌、ZIP、单 HTML、文件路径与权限回归 | 安装环境中 21 项通过（16 项内容处理与签名、5 项权限） |
| 打开不存在的分享、请求不存在的内容、直接访问解包目录 | 返回 404，内容响应不设置 Desk 会话 cookie |

保留的[合成公开示例](http://127.0.0.1:8080/s/wkkKUdmvqi)显示 ZIP 第 2 版。Chrome 截图中可见标题、条纹图片和脚本加载结果。具名授权撤回后，原会话与独立会话重取受限内容均返回 403；停用后的外壳和内容均返回 404。原件也通过 Frappe 下载接口单独验证了拒绝访问。
