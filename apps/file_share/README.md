# 文件分享

员工在 Desk 发布 HTML 报告或 ZIP 静态站点。一份报告只有一个区分大小写的分享 ID、一套版本历史；每个发布域名对应一个独立入口，收件人使用 `https://<域名>/file-share/s/<10 位分享 ID>`。应用依赖 Frappe v16 和 ERPNext Employee。

员工可通过 [CLI、HTTP API 和 Agent](EMPLOYEE_API.md) 查询自己的报告、上传草稿、向指定域名发布或回退版本、关闭入口。

## 管理员：接入分享域名

在文件分享应用的「分享域名」登记名称和完整外部地址（例如 `https://reports.example.com`），先设为待接入。DNS、HTTPS 和 Nginx 配置由运维完成，参考[生产渠道代理样例](../../deploy/prod/share-domain.conf.example)及[开发站说明](../../deploy/local-pg/README.md)。验证从外网可访问后再启用；登记本身不会部署代理或签发证书。普通员工没有配置页权限，只能在分享表单里选取可用域名。启用新域名不会开放任何既有报告。停用域名影响其下的全部报告；关闭报告的一行发布入口只影响该报告。

## 员工：发布和切版

1. 应用默认打开「文件分享」列表 `/desk/file-share`。新建分享，填写客户能识别的标题，选择自己的私有 `.html`、`.htm` 或 `.zip`。ZIP 推荐在根目录使用 `index.html`，用相对路径引用包内经典 JS、CSS、图片；也支持唯一顶层目录内的 `index.html` 或根目录中唯一的 HTML。
2. 设置报告的默认查看范围，添加一个或多个发布域名。如果只有一个可用域名，表单自动选择。每一行可以继承或覆盖默认权限，包括设置独立密码或指定人员/角色。首次正式发布至少需要一个已启用的入口。
3. 可以仅上传并保存草稿，或选择本次上传后发布。在已开启、支持员工登录的域名上，在职作者可预览某一版。将已有版本设为当前发布版即发布或回退；跟随当前版的入口同步切换，固定版保持不变。也可以只修改某个域名的固定版本。发布端变更版本不会改变客户链接或要求重新输入未变的入口密码。
4. 保存后在对应域名一行复制链接。停用整份报告会同时关闭全部域名和资产。服务器为每版生成入口文件、大小、上传人和时间；版本文件不因切版而重新上传。

| 查看范围 | 打开已授权域名的条件 |
| --- | --- |
| 内部员工（默认） | 已登录的在职员工 |
| 指定人员或角色 | 在职作者，或符合该入口允许用户/角色的在职员工 |
| 密码 | 在该域名输入正确口令，或在职作者登录 |
| 公开 | 任何持有该域名链接的人；不能用域名证明收件人身份 |

外部客户不因使用渠道域名而获得员工身份。不同域名不共享浏览器登录或口令 Cookie。渠道代理样例只开放分享页面和资源，不开放 Desk 或登录；需要员工登录的入口必须另行配置并验证该域名登录流程。

发布账号须为启用的 `System User`。公司移山 ID 登录校验当前会话在职有效期和账号绑定；使用站点密码登录须关联 `Active` Employee。员工管理自己的分享及访问记录。System Manager 可管理分享、审计和域名；无在职身份的管理员可停用或删除已有分享，但不会因此获得报告历史预览、指定人员或密码入口的查看权。

## 访问记录、旧链接与迁移

「访问记录」位于文件列表之后，地址 `/desk/file-share/access-log`。每条新日志保留访问时的文件标题、分享 ID、域名、版本、结果等。原日志能关联到报告的回填现有标题；不能还原的旧标题和历史访问域名不伪造。

迁移前确认 `file_share_primary_origin` 为旧链接真正对外使用的源地址（例如开发站 `http://127.0.0.1:8080`），否则使用明确配置的 `host_name`，正式同名站点可识别原正式域名。已有数据而不能确定原地址时迁移会停止。存量分享仅绑定该域名，保留既有权限、密码和发布版。旧 `/file-share/<ID>`、`/s/<ID>`、历史 `?v=` 及旧资源地址继续受同一份域名、权限和版本规则控制；旧 Desk 书签继续可用。切勿把其他域名批量加入所有报告。

## 文件、会话与撤权

上传原件存于站点 `private/files`，发布副本在 `private/files/.static_share/<ID>/<版本>`。备份或恢复时同时保留数据库、私有文件与站点加密密钥。Nginx 不得直接提供私有文件。HTML 和 ZIP 报告可直接引用 HTTPS 外链脚本（例如 CDN 上的 ECharts）。浏览器打开报告时从对应地址加载，外链可用性取决于收件人的网络及第三方服务。发布人应信任引用的脚本来源：外部脚本可以读取或修改报告内容，浮动版本也可能在发布后变化。报告在 `sandbox="allow-scripts"` 的 iframe 中运行，内容响应也发送 CSP sandbox。样式、图片、字体和媒体继续遵循原有资源范围，表单提交、嵌套框架、Fetch 和 WebSocket 仍受禁止。需要在线数据的报告可把数据嵌入 HTML。

每个资源请求都会重新解析域名和有效版本。受限资产需要带有效期的路径和独立的 HttpOnly Cookie（`Secure; SameSite=None`），因此生产要求 HTTPS。员工授权重查原登录会话、账号和访问规则；退出、离职或撤权后，新请求被拒绝。页面凭证有效期 30 分钟。入口密码使用 Frappe 加密 Password，验证状态最多 7 天；同报告、域名和来源 IP 连错 10 次限流 15 分钟。切版会作废旧资源凭证，但不清空未变化的密码验证状态。无法收回收件人已经下载或截图的内容。

## 验证

- 不依赖站点：在安装本应用与 Frappe 的 Python 环境执行 `python -m unittest discover file_share/tests`；Desk 路由使用 `node --test file_share/tests/desk-routes.test.cjs`。
- 隔离 PostgreSQL 验收：仓库根目录运行 `rtk proxy bash deploy/local-pg/share-qa/run.sh`。使用一次性 Compose 项目及合成报告，不连接开发库或生产环境。
