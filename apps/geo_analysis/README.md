# 数据分析

入口 `/desk/geo-analysis`；安装标识 `geo_analysis`，标准模块 `GEO Analysis`。先安装任务执行和服务管理。首版使用 Frappe Desk 标准单据，由 System Manager 制作分析；服务查询走单独的授权接口，不向成员开放全局回答表。

## 从一个回答出报告

1. 在数据分析工作区的「标的与竞品版本」选择服务，填写与该服务标的一致的名称，别名和竞品每行一项。新名单另建版本。
2. 在「分析口径版本」说明适用规则。拒答选择 `Exclude`（不计分母）或 `Include as miss`（计分母，未命中）。这两种为首版支持的口径，不替客户决定合同规则。
3. 新建「样本复核」，选择服务、应采记录和上述两个版本，点「查看原始回答」。按约定的竞品范围和证据人工复核推荐名次，填写名次和回答的逐字摘录。`Ranked` 为可判定名次，`Unranked` 为未排名，`Refusal` 为已采到的拒答。不会将文本中首先出现的名称当作首位推荐。另存精确名称或别名命中、原文摘要、复核人和时间；命中名称不意味着正面推荐。
4. 在「指标报告」指定服务、期间、口径、标的与竞品版本，可限定服务问句或平台能力。保存时按站点时区、应采窗口起始日期取样，只有观测时间在 `[window_start, window_end)` 中的回答才被采纳。报告同时保存应采、实采、复核数、Top 3 分子/分母、精确提及率，以及逐行的纳入、待复核或排除状态。未复核不等于未命中；分母为零显示「无有效样本」。
5. 展开报告明细中的复核记录，点「查看原始回答」核对原文与有序信源。无信源与未取得信源分别保留 `[]` 和 `null`。重审新建复核记录，用同一组版本生成新的报告，先前生成的报告仍引用当时采用的复核记录。每个报告对同一个回答最多计一次。报告不是合同期末自动达标判定。

## 成员查看

登录后打开 `/geo-review`，选择有权查看的服务和采样日期即可查看应采/实采与回答。页面列出该服务最近的报告，从报告明细可点进复核摘录、原文和有序信源。未获授权的服务不在选择列表，直接访问其他服务的链接也会被拒绝。

## 对接与权限

- `geo_analysis.api.read_report(service, report)` 返回该服务的冻结计数和明细，可按 `included`、`hit`、`mention_hit` 自查分母、分子和精确提及计数。
- `geo_analysis.api.read_sample(service, sample)` 返回授权复核记录及原文、原始信源顺序、实际采样条件、可用的分享地址。`geo_analysis.api.read_slot(service, slot)` 在复核前查看已采纳的证据。
- 三个接口都先验证当前用户的服务权限，再沿服务自身的应采记录查原始回答。调用方无需获得全局任务标识、账号、代理或其他客户信息。上传和展示截图、平台级自动排名、模型判定和合同期末判定不在本次分析交付范围。

## 验收

纯口径测试：仓库根运行 `rtk proxy env PYTHONPATH=apps/geo_analysis python3 -m unittest discover -s apps/geo_analysis/tests`。跨应用验收可在独立预览站使用两个测试服务，创建同问句同窗口的共享回答，分别复核两个标的，检查服务 A 只有自己的报告和证据。再次复核并另出报告后核对旧报告不变；对拒答分别核对两种分母口径。
