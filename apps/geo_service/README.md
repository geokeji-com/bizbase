# 服务管理

入口 `/desk/geo-service`；Frappe 模块 `GEO Service`。安装依赖 ERPNext 和任务执行。

1. 在「服务档案」选择现有 ERPNext 客户和该客户的合同，记录实际被服务组织、优化标的、负责人、成员有效期间以及合同考核条件。
2. 添加「服务问句」，填写目标名称和监测起止日。原文只去首尾空白；系统按原文精确判重。换词使用新记录并给出确认人、理由和生效日。旧词保留历史。
3. 建立「监测计划」，从已启用的问句采集能力中选平台和端，配置该版本支持的参数，添加服务问句及采样时窗，设置时区、星期和独立样本数。每个时窗按样本数等分；每个独立窗口产生一条应采需求。第一版支持周内重复及显式时窗，不含随机时间分布与跨午夜单个时窗。
4. 在计划页按某天预览或「生成并派发」。每小时定时作业也会为计划当地的当日与次日建立应采记录并派发。已过窗未派发的记录保留缺口。参数和时间范围满足多项服务时，任务执行可共享一次实际采集。服务暂停继续采集，关闭不再派发新任务。改计划选择「创建下一版本」；旧版本已经生成应采记录的日期不允许回改。换词后，另建计划版本纳入新问句。
5. 打开服务详情的「采集进度」，查看按计划日期的实采、应采和过窗缺口。采集状态按任务执行确认接收的结果判定；回答拒答和品牌是否达标由数据分析独立处理。

**权限**：服务主档、计划、全局问句和任务引用的原生 DocType 仅对 System Manager 开放。已登录的服务负责人或在授权有效期内的成员可通过 `geo_service.api.my_services`、`geo_service.api.preview(plan,date)` 和 `geo_service.api.coverage(service,date)` 查看本服务投影；后两者拒绝其他服务，覆盖统计不会返回共享任务 ID。Worker 通过任务 Server 领取，不能由此获得服务成员权限。

**数据关系**：`GEO Service → GEO Service Prompt → GEO Monitoring Plan（独立版本记录）→ GEO Sampling Slot → Execution Task → Execution Result`。`GEO Prompt` 保存全局不可变原文。成员、标的和考核条件是服务子表，采样时窗、问句选择是计划子表。每个应采记录固定计划版本、问句、标的、能力与时窗。任务重传不创建新的应采记录。

**时间口径**：服务与计划以含首尾的日期生效，计划时区决定采样日期，实际窗口换算为站点时间。计划只接受 `prompt` 能力；链接状态检查可直接使用任务执行的接口。工作区的原生写表单供管理员使用。服务规则记录阈值和合同依据，尚未实现自动期末结算。
