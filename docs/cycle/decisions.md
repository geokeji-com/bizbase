- 采集系统独立，由本项目定义拉取任务、回传结果的 API，移动端采集程序兼容该格式。第一版平台：DeepSeek、豆包 APP 端。

### D-026 问句判重规则与共享采样条件（2026-11-18；用户明确指令）

- 用户指令：“共用采样，首先这种情况不会特别常见；其次，就要看能不能用一条采集任务满足条件了。如果不能满足，就会采多条。”
- 用户补充：“采集的时候不光有问句，还有采集的一些参数呢。所以共用的其实是 AI 的回答，但 AI 的回答能不能共用，首先要看采集任务能不能复用。”

- 决定：共享采集是优化，不是强制。调度时只有一条任务能同时满足各计划的要求（问句、采样条件、时间窗口，以及随机或均匀分布等时间要求）才共用；不能同时满足就分别生成任务。合同对采样的要求优先于节省采集量。

### D-029 系统可通过 CLI 与 Agent 操作（2026-11-18；用户明确指令，做法参考 jkstone）

- 用户指令：“jkstone 这个项目是之前尝试做 Open API 时的一个小尝试，里面会给 CLI 或者 Agent 开放 Key，然后让 Agent 或者 CLI 来使用，我觉得这还挺好的。当前项目也需要考虑到这些哦。”用户随后更正：“我的意思是参考这个思路，要实现可以通过 CLI 或 Agent 操作的途径。而不是接入它。”

- 参考 jkstone 的思路（本机 `jia_keystone`：`ApiCredential`、`CapabilityGrant`、`skills/jkstone/SKILL.md`）：
  - 凭证分两类：个人凭证代表某个人，CLI 或 Agent 使用时权限与这个人相同；应用凭证代表一个程序（采集程序、报告 Agent），只授予需要的能力。
  - 带前缀的 Key、只存哈希、明文只显示一次、有效期、IP 白名单、轮换时新旧并存、可撤销、调用可审计。
  - 能力编码 `对象.能力`，凭证只能调用已授权的能力，按凭证限流；统一响应格式与中文错误信息；接口契约文档；CLI 输出 `--json`；配套 skill 让 Agent 安装后即可使用。
- 实现方式（Agent 推荐，可逆）：在 Frappe 内实现；个人凭证可基于 Frappe 用户 API Key，使行级权限自动生效；能力授权、有效期、IP 白名单、轮换和用量记录补在 GEO 运营 App。CLI 的技术选型与浏览器授权登录方式在实施轮次确定。
