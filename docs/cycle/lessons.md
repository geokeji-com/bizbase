# 项目经验

本项目在开发全过程中验证过的教训。只追加，不改写；推翻旧经验时新增一条，在旧条目状态写"已作废，被 L-xxx 取代"。通用的经验经用户在决定清单里批准后升级到技能的 `lessons.md`。

### L-001 所有输入保留证据性质，不能自动变成裁决
- 阶段：any
- 适用：结合口述、SOP、竞对材料和仓库实现做方案。
- 规则：记录来源、日期及事实/推断/未知；候选方案经实际样例验证再申请裁决。源码存在不等于现网有效，也不等于最佳方案。
- 证据：142 仓盘点后出现多份主数据归属声明；用户明确指出四类输入都不一定是真理。
- 来源：BizBase，2026-11-18 用户指令及 evidence.md E-01—E-05。
- 状态：生效

### L-002 服务项不能同时表示履约单位和问句名额
- 阶段：discover
- 适用：换词、范围版本及服务层级建模。
- 规则：先核对既有词汇含义；不同生命周期与授权边界的概念不复用同一名称。真实样例未齐时保持明确的未决项。
- 证据：独立审查发现候选模型一处用服务项承接名额，而词汇表将其定义为可独立授权、暂停、考核的履约单位。
- 来源：BizBase，2026-11-18 独立审查；geo-service-model.md 第 2.2 节已更正。
- 状态：生效

### L-003 按实际入口确认 Build 与 Builder
- 阶段：any
- 适用：用户询问名称相近的 Frappe 功能。
- 规则：先查 URL、当前安装清单和拥有该入口的源码，区分框架工作区与独立 App。
- 证据：此前将 Build 理解为 Builder；核实 /desk/build 后确认它是框架自带工作区，本地仅安装三个 App。
- 来源：BizBase，本次会话 2026-11-17 的 Build 链接澄清及本地源码检查。
- 状态：生效

### L-004 缺口展示不能替代真实业务路径的成功验收
- 阶段：discover
- 适用：只读集成试点的验收条件与确认清单。
- 规则：至少要求一条完整真实关联成功；全是缺口只能算诊断结果。业务原则确认与新选首轮方向确认分别明确，不能相互代替。
- 证据：第二次审查发现“可追溯或标缺口”允许零条成功关联也通过，且只接受三项原则未必确认新增首轮路径；两处均已修正。
- 来源：BizBase，2026-11-18 第二次独立审查；proposals/first-slice.md、sheets/decision-sheet-01.md。
- 状态：生效

### L-005 先完成整体自然式规划，再按行动开展小轮次
- 阶段：any
- 适用：本项目制定首轮与后续实施节奏。
- 规则：遵循用户明确的五步分工，首轮做完前四步；Action 用 ratchet 管理，争取日版本。已确认的规划直接引用，具体模型和发布记录仍以真实证据为准。
- 证据：Agent 原先先推荐文章回链切片，用户要求改为先做全局目标、成果、头脑风暴和组织管理；旧清单三项仍未答。
- 来源：BizBase，2026-11-18 用户指令与 D-002；旧清单现位于 archive/decision-sheet-01.md。
- 状态：生效

### L-006 流程调整后检查旧的首轮含义是否同步
- 阶段：any
- 适用：整体规划轮与实施轮次重新分工。
- 规则：搜索旧方案中的首轮、下一步和确认顺序，逐处区分历史描述与当前指令；仅更新当前指令，不把未答问题当成接受。
- 证据：D-002 传播后独立审查仍发现模型一处“收敛首轮最小模型”，与首轮整体规划的新含义不一致；已改为按选定实施轮次收敛变化。
- 来源：BizBase，2026-11-18 自然式规划独立审查；geo-service-model.md 模型确认缺口段。
- 状态：生效

### L-007 接口文档和当前源码冲突时先分层核验
- 阶段：discover
- 适用：根据既有接口选择接入范围与真实样本。
- 规则：同时记录文档版本、拥有实现的当前源码和实际部署响应；三者冲突时明确各自证明范围，未实测前不宣布当前接口一定能返回或一定排除某类数据。
- 证据：首次进度说明依据旧文档判断接口排除“待核对”对象，随后发现当前源码已包含该类型；已及时更正，生产响应尚未核验。
- 来源：BizBase，2026-11-18 行动取证 E-07；私有样本记录保存文件与行号。
- 状态：生效

### L-008 切片改变后同步证据门槛与模型图含义
- 阶段：discover
- 适用：从整体规划收敛或更换第一条实施路径。
- 规则：每项证据缺口注明适用场景；概念图明确区分已观察关系、实际字段和拟议字段；新增独立记录用语同步到词汇表。
- 证据：独立审查发现文章—发布关联仍处于通用最小模型门槛、概念字段被写成实际 schema、三项候选记录缺词汇入口；已分别更正。
- 来源：BizBase，2026-11-18 确认传播独立审查；evidence.md、proposals/directory-query.md、GLOSSARY.md。
- 状态：生效

### L-009 把认证、业务授权与证据覆盖范围分别写入验收
- 阶段：discover
- 适用：复用框架身份和日志，为自定义业务 API 制定模型及验收。
- 规则：区分进入方法前的认证拒绝与方法内的业务拒绝，各自验证真实日志路径；配置项为零只证明该配置项状态，不能推断所有接入方式均不存在；来源身份角色须独立定义。
- 证据：最小模型独立审查发现审计验收把两层拒绝混在一起、SSO 结论超出 Social Login Key=0 的证据，且登记客户/交付客户缺独立定义；已修正。
- 来源：BizBase，2026-11-18 目录模型独立审查；directory-acceptance.md、directory-model-views.md、evidence.md、GLOSSARY.md。
- 状态：生效

### L-010 正式实施轮建立后更新候选验收入口
- 阶段：design
- 适用：模型确认后将候选路径转为正式实施轮。
- 规则：保留候选稿作为历史，但把所有当前验收入口指向正式轮次，并移除已完成阶段的等待措辞。
- 证据：第 01 轮已建立并填写验收/预算，独立审查仍发现候选稿称“模型获确认后移入”，取证入口也继续指向旧稿；已更正。
- 来源：BizBase，2026-11-18 第 01 轮 readback 独立审查；proposals/directory-acceptance.md、directory-query.md、backlog.md。
- 状态：生效

### L-011 唯一约束测试使用框架实际异常类型
- 阶段：build
- 适用：Frappe 中验证复合唯一索引。
- 规则：在真实数据库上确认冲突对应的异常类型；复合唯一索引冲突断言 UniqueValidationError，不把主键重复异常当成所有唯一冲突。
- 证据：首轮 4 项模型测试中 3 项通过；唯一索引实际生效，但测试误期望 DuplicateEntryError，已按实际异常修正。
- 来源：BizBase，2026-11-18，第 01 轮 test_bb_customer_reference.py。
- 状态：生效

### L-012 将实施前基线与当前运行状态分开
- 阶段：build
- 适用：领域模型确认后进入实际开发。
- 规则：模型中的旧检查结果明确标为实施前基线；当前进度只引用执行证据，并重新生成状态索引。
- 证据：独立审查发现 2 处“尚未实施/尚无 App”与已安装 App 冲突，以及 1 处生成索引仍指向旧 compose 文件名；已同步修正。
- 来源：BizBase，2026-11-18，第 01 轮 decision_review；GLOSSARY.md、directory-model.md、STATUS.md。
- 状态：生效

### L-013 提交事务的集成测试必须显式恢复夹具
- 阶段：build
- 适用：管理动作和审计会真实 commit 的集成测试。
- 规则：为测试分配独立命名空间，逐项恢复状态、跨项清理新增引用，并记录删除过的引用 ID 供最终清理；不依赖测试框架 rollback。
- 证据：静态自审发现并发切换用例留下 1 个 V2 引用，会污染后续失败回滚断言；在真实 DB 运行前补齐显式清理。
- 来源：BizBase，2026-11-18，第 01 轮 tests/test_directory.py。
- 状态：生效

### L-014 直接调用 Frappe 前固定站点工作目录
- 阶段：build
- 适用：在容器里绕过 bench 命令封装执行受控管理脚本。
- 规则：先切换到本 bench 的 sites 目录，再用匹配的 sites_path 初始化 Frappe；不要假设日志路径由绝对站点路径完全决定。
- 证据：首次 seed 在连接数据库前因 ../logs 定位到错误目录而失败；校正工作目录后四个隔离身份成功创建。
- 来源：BizBase，2026-11-18，第 01 轮 scripts/directory/site_ops.py；Frappe utils/logger.py。
- 状态：生效

### L-015 审计验收按真实日志字段定位
- 阶段：build
- 适用：复用 Frappe 原生权限变更日志。
- 规则：核对实际 Permission Log 的 for_doctype 与 reference_type 含义后写断言；不能因过滤字段错误把已持久化日志误报为缺失。
- 证据：HTTP 验收查询错字段而报零，实际有 21 条权限日志，授权变更对应 for_doctype=User Permission；已修正查询。
- 来源：BizBase，2026-11-18，第 01 轮 http_checks.py 及真实隔离数据库。
- 状态：生效

### L-016 恢复验收必须先验证恢复态再初始化
- 阶段：build
- 适用：同一聚合命令同时承担干净初始化验收和备份恢复复验。
- 规则：恢复后先比较备份时状态与授权摘要，并用原凭据读取；跳过 seed，避免自动补数据掩盖恢复丢失，再进行后续回归。
- 证据：独立审查发现旧聚合命令会先重建 4 个身份及授权再确认恢复，可能产生假阳性；已新增恢复前摘要校验及禁 seed 分支。
- 来源：BizBase，2026-11-18，第 01 轮 code_review；site_ops.py、recovery.py、verify_round01.py。
- 状态：生效

### L-017 浏览器登录选择器以当前页面为准
- 阶段：build
- 适用：跨 Frappe 版本运行端到端登录测试。
- 规则：核对实际模板或浏览器 DOM，使用当前登录表单的 submit 按钮，不沿用旧版本 CSS 类名。
- 证据：实际登录表单能填入两项凭据，但旧 .btn-login 选择器超时；当前 16.56.0 使用 .for-login 内 type=submit。
- 来源：BizBase，2026-11-18，第 01 轮 browser/acceptance.mjs；Frappe www/login.html。
- 状态：生效

### L-018 本地检查点包含配套消费者凭据
- 阶段：build
- 适用：独立客户端凭据存于数据库之外的私有文件。
- 规则：seed 重放复用既有测试凭据；检查点同时备份、校验和恢复对应的私有凭据文件，避免数据库恢复后客户端仍使用较新密钥。
- 证据：独立审查指出“备份 A、seed B、恢复 A”会使 4 个账号的本地凭据失配；已补 seed 幂等与检查点配套文件。
- 来源：BizBase，2026-11-18，第 01 轮 code_review；seed_demo.py、recovery.py。
- 状态：生效

### L-019 验证当前框架的 Desk 初始化门槛
- 阶段：build
- 适用：同站安装 Frappe/ERPNext 后只验收一个独立 App。
- 规则：核对当前 is_setup_complete 实现及实际跳转；隔离测试可显式跳过安装向导，但必须注明并未配置 ERP 财务或公司，不创建虚构业务数据。
- 证据：API 已通过，普通浏览器仍被转到 setup-wizard 并 403；16.56.0 实际读取 Installed Application 而非旧 System Settings 字段，已按源码修正隔离初始化。
- 来源：BizBase，2026-11-18，第 01 轮 seed_demo.py、私有 browser-diagnostic.json；Frappe __init__.py。
- 状态：生效
