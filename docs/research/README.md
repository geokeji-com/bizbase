# BizBase 调研记录

## 2026-11-17：官方应用与 GEO 业务建模

本轮按用户要求，先分批提交并推送既有部署和项目定位变更，再调研官方应用与 GEO 厂商。尚未获得公司的完整 GEO 业务介绍，因此以下应用选择和模型均为建议，不代表已决定安装、替换现有系统或迁移生产数据。

### 建议阅读顺序

1. [Frappe 官方应用适用性](2026-11-17-frappe-apps-assessment.md)：保留什么、哪些可试评、哪些按需求选装，以及固定版本证据。
2. [海外 GEO 厂商流程](2026-11-17-geo-vendor-workflows.md)：Profound、Scrunch、Peec AI、OtterlyAI、Semrush 的产品流程、指标差异与对象。
3. [国内 GEO 服务链](2026-11-17-geo-china-evidence.md)：微盟星启、智推时代、监测工具与平台资料，区分公开事实、营销自述和信息缺口。
4. [GEO 能力与数据模型候选方案](2026-11-17-geo-domain-model-candidate.md)：将研究转成可讨论的对象边界、关系图、指标与接入验证场景。

### 当前建议

- 继续使用现有 Frappe、ERPNext、CRM，没有因“要建数据底座”而必须立即补装的官方 App。
- Insights 在有真实跨系统报表问题时优先试评；Wiki 在需要统一发布接入文档和 SOP 时试评；其余按明确业务需求选装。版本与依赖证据见应用报告。
- 共享数据优先覆盖主体/品牌/服务关系、品牌事实、内容版本、问题集版本、采样证据及指标定义。每种事实明确维护方，上层应用可以保持不同界面和分析方法。
- 各厂商同名指标未必同义；原始证据、分母、采样条件和计算版本必须可追溯。内容发布、获引、提及、访问与成交分别记录。
- 下一步听取公司的真实服务流程，再收敛术语、对象基数、状态、权限、验收和首批接入范围。本轮不预先把候选模型写成正式业务表。

### 验证范围

本轮查阅公开官方文档、发布源码与厂商一手说明，未进行新增 App 组合试装、厂商付费后台测试或 GEO 效果实验。报告中已标注搜索索引与当前页面不一致、版本文档漂移、未公开口径等限制。引用均位于对应报告的事实附近。
