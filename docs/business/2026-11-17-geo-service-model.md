## 1. 已了解到的实际业务

### 1.1 业务目标与问题

- 公司从 2025 年 8 月开始开展 GEO。早期以全包服务为主：销售签单后，准备资料、生成文案、发布、采集监测、分析，再继续优化和投放。
- 合同包含 Top 5、Top 3、可见度等表现要求。前文“Top 50、Top 300”为转述错误，已由用户纠正；具体验收公式、分母、周期和阈值组合尚未确认。
- 过去客户、问句与投放规模增加，依赖人员扩张；个人电脑、个人 skill 和手工投放导致方法分散、成本不透明、发布链接未回收，出现接单增长而亏损加重的问题。此处为用户对经营状况的描述，本轮未做财务核算。
- 建设 BizBase 的目标是统一业务数据和基本能力。不同岗位仍可以制作不同界面与应用；重复界面可以存在，客户资料、服务范围、证据、发布记录和权限需要对得上。

### 1.2 自营获客与销售

- 公司有一个主品牌、五个子品牌，各有官网。官网既用于留资，也用于发文，成为自有信源。公司自身也会按客户视角进行问句设置、监测和优化。
- 线索入口包括官网、小红书、抖音、微信服务号、400 电话和活码。活码可能将不同联系人路由到不同销售。
- 线索通过表单、平台 API、人工识别与飞书表格等方式汇集。有的已有销售归属，有的还需分配；具体规则不能简单按“API 接入就一定未分配”判断。
- 销售跟进判断意向。高意向客户会参加销售主导、运营参与的服务介绍会议。
- 签约前进行拓词和售前诊断，向客户展示较大范围候选问句的表现，再协商服务哪些问句。用户末段也使用“授权诊断”一词，其是否指独立授权环节尚未确认。
- 拓词依据包括行业、品牌、产品、百度指数、微信指数、小红书指数和搜索联想等。用户重视选词依据的可解释性；不希望仅凭 AI 生成结果解释选择理由。

### 1.3 服务与采集

- 签约后召开项目启动会、准备客户资料，再开展优化。优化执行包括内容生成和发文投放。
- 签约和服务关系包含：A 公司签约并服务自身；总部签约并服务总部或分公司；渠道签约并服务渠道客户。优化标的可以是公司、品牌或产品。
- 问句过泛、AI 拒答或不出现品牌等情况下，可能与客户协商换词。还存在服务暂停，以及年框合同每三个月更换一批问句等安排。
- 监测采用探针方式，不能直接知道真实用户搜索总次数或每次回答。采样入口包括 App、网页和官方 API；使用的平台、端、Chat/Work、联网、思考、深度搜索及强度等条件会变化。
- 日程可能为每日一次、每周三次、指定时段每小时、全天若干次，并可能要求随机或均匀分布。
- 采集的核心产物是问句、AI 回答和信源列表。RPA 采集还可以取得分享链接、截图。

### 1.4 实体分析、信源与报告

- 系统维护目标实体、名称、官方或俗称别名，以及竞品名称，分析目标与竞品的相对位置。产品 B 可以是客户 A 的优化标的。
- 效果统计由问句级向监测任务级、整体数据级聚合。监测任务与问句、平台之间的具体组织方式仍需对照现有系统确认。
- 可见度可能使用程序匹配；Top 分析可能使用不同 AI 模型和版本。排名含义、分析策略及版本都会影响结果。
- 信源包含文章、视频、商品卡片；链接可能直达、跳转或返回 404。“厂商缓存了旧信源”是用户提出的可能解释，不是已经核实的原因。
- 信源需去重，并补充标题、内容等，为后续内容生成准备材料。运营还分析各平台中不同内容的引用率，再决定投放方向。
- 报告从 Excel，发展为 JSON、HTML 单周/双周报告及跨期比较，进一步提供含指标和信源的客户看板。

### 1.5 内容、投放和经营管理

- 目前专门小组根据表现薄弱的问句，从词根、意图和场景等角度生成相关内容。
- 通过聚合发布平台接口投放公众号、新浪、地方融媒体等渠道，并取得发布链接。用户希望这些基本能力纳入当前底座。
- 外部单篇投放价格可能从几元到几十元、上百元。历史投放成本和链接回收不完整，需要建立追溯。
- 销售分成、运营分成、考核节点与投放成本核算均需进一步确定。本文不自行设定比例、提成触发点、成本扣除或暂停顺延规则。

## 2. 建议的业务结构

### 2.1 统一主体身份，分别表达业务角色

建议区分以下对象及角色：

| 对象/角色 | 含义与边界 |
| --- | --- |
| 组织主体 | 公司、总部、分公司、渠道、供应商等共同身份。集团关系和合作关系分别表达，不统一塞进一棵父子客户树。 |
| 签约角色 | 在某一合同中作为签约方；与付款方是否相同需另行确认。 |
| 被服务组织 | 实际接受该服务的组织，可以与签约方不同。 |
| 优化标的 | 具体公司、品牌或产品。身份稳定，名称和别名可变化。 |
| 获客品牌/入口 | 公司用哪个品牌、站点或账号获得某次线索，与客户的优化标的分别记录。 |
| 服务实例 | 对一个明确范围持续履约的业务关系，关联合同、参与组织、优化标的和责任团队。 |

同一组织可以在不同业务中承担不同角色。公司自身的品牌运营也可使用同一套采集、内容和投放能力；用内部业务范围标识归属，不为内部工作虚构客户合同。

总部—分公司关系与渠道—终端客户关系在“签约方与服务对象分离”上相似，但组织性质、商业责任和授权依据不同。不能因为渠道签了合同，就自动授予其终端客户的所有历史、其他合同或全部品牌数据。

### 2.2 用服务范围版本承接换词、年框与暂停

候选关系：`合同/商业约定 → 服务上下文 → 服务范围版本 → 问句配置与指标约定`。这里的“服务上下文”是尚未定型的统称；范围版本直接属于服务实例，还是属于其下可独立履约的服务项，需用真实样例核对后决定，当前不据此建表。

- **服务实例**承接持续履约，换词通常不必切断整个服务历史。
- **服务范围版本**记录某段时间服务哪些标的、问句、平台条件与约定；生效时间、变更原因和确认依据需保留。
- **问句身份与版本**分别记录。文案修订、翻译、场景变化、完全换题都保留关联，但不一概视为同一测量对象。
- **替换记录**连接旧问句配置与新问句配置。若合同确有稳定问句名额，其承载方式单独核对，不能复用“服务项”这一履约单位的含义，也不能在未确认前强制“一旧词换一新词”。
- **暂停记录**说明作用于整个服务还是部分范围，并分别确定采集、生成、投放、报告、计费及验收的处理方式。暂停不自动意味着合同顺延。
- 年框、服务执行周期、换词批次、报告周期和结算周期分别表达。三个月换词不必等同自然季度，也不必等同一份新合同。
- 暂停前派出的采集或投放可能在暂停后返回结果；保留事实，再按规则决定是否纳入本期交付或验收。

看板的连续性分为三层：

1. **服务时间线连续**：展示启动、换词、暂停、恢复、范围变更和报告交付。
2. **当期表现完整**：按当期实际问句和规则计算，明确对应的范围版本。
3. **跨期比较诚实**：显示相同条件的可比子集，或分段呈现。不同问句、竞品集合或采样方式不能未经说明拼成同一趋势。

售前诊断保留全部候选及筛选依据；签约后的服务范围引用入选问句和确定的基线批次。筛掉本来表现高的问题后，不能拿售前全集直接与签约子集比较并将差异全部归为优化成果。

## 3. 从实体到整体指标的可追溯链

### 3.1 实体、名称与比较集合

| 候选对象 | 作用 |
| --- | --- |
| 实体 Entity | 稳定识别公司、品牌、产品；分析目标和竞品是其在某个比较范围中的角色。 |
| 名称/别名规则版本 | 保存规范名、官方称呼、俗称、语言与适用范围；同名或歧义需要消歧，不能任意子串命中。 |
| 比较集合版本 | 固定某次排名分析考虑哪些目标和竞品。新增、删除、合并竞品产生新版本。 |
| 排名策略版本 | 明确如何从回答确定相对次序、如何处理并列、未提及、否定举例和非推荐列表等。不能默认“首次出现位置”就是推荐排名。 |
| 分析执行记录 | 保存证据 ID、实体/别名/集合/策略版本，使用的分析模型、可知版本、提示模板、参数、输出及复核情况。 |

目标是“产品 B”时，应明确其与公司 A、品牌 A 的关系，不能把出现公司名自动算作产品 B 达标。是否允许这种映射需由指标策略明确。

按用户当前描述，Top 主要比较目标与竞品实体的相对位置；名单之外的品牌是否也占据排名位置仍需确认。不能无依据宣传成所有品牌中的全市场排名。合同验收按已确认定义执行。

### 3.2 竞品变化后的两类历史视图

- **历史口径视图**：保留当时范围、比较集合、别名规则和分析策略下的结果；已交付报告引用它们，不被静默改写。
- **同口径复算视图**：选择一个明确版本组合，对有足够原始证据的历史区间重新分析，再比较这些新结果。新结果记录为重算，不替换原结果。
- 原始回答不足、证据不可访问或条件不可比时，说明无法复算或不可直接同比。重新访问 AI 平台只能产生当前新观测，不能补造历史回答。
- 竞品变化本身可能改变相对名次，即使回答原文没有变化。因此图表应标注“比较范围变化”，避免把名次变化直接归因为优化效果。

### 3.3 按用户的三个层级聚合

`采样证据 → 分析结果 → 问句级汇总 → 监测任务级汇总 → 整体汇总`。

“监测任务”是业务上的监测组织单元，其定义需对照现有系统；“执行批次”和“执行尝试”是实际运行记录，不能混用。整体数据所覆盖的客户、服务、品牌与时间范围也必须显式指定。

候选结构为 `监测任务 → 有效配置版本 → 执行批次 → 问句采样 → 版本化分析`。竞品更新、日程调整不必重建任务；每次运行保留实际绑定的配置。名单中的排列顺序只是配置顺序，不应成为分析得到的名次。

建议每个汇总携带统计范围、版本组合、分子/分母、样本数量、失败/排除情况和计算时间。按回答加权、按问句等权、按平台等权可能得到不同结果，需明确选择，不能直接平均已有百分比或平均名次。

若要展示“Top 3 达标率”，可定义“满足名次条件的评价单元数 / 纳入评价的单元数”，但以下尚待确认：评价单元是一次回答还是一个问句在周期内的结果；未提及、拒答、无品牌回答如何处理；频次不同的问句是否等权；哪些平台和期间纳入合同验收。此公式仅为讨论示例。

必须分开记录三种状态：**采集是否成功、回答能否按策略评价、评价是否达标**。AI 正常返回拒答，与请求超时不是同一种情况；两者对指标的影响由版本化规则决定。

## 4. 采样计划、证据与信源

### 4.1 计划配置与实际执行分别保存

候选链：`问句版本 + 采样配置版本 + 日程 → 计划采样单元 → 执行尝试 → 原始回答与证据`。

采样配置包括平台、产品/端、App/网页/API、Chat/Work、联网、思考/深度搜索条件、语言地区及必要上下文。平台不支持的参数记为不适用，无法确认的实际模型记为未知。记录计划条件，也记录实际运行偏差。

日程至少表达时区、有效时间段、频次、分布要求（均匀/随机等）和计划时间点。保留计划时间、实际开始/结束时间及重试。暂不自行认定“24 小时三次”必须每八小时一次；错过时段是否补采、重试是否跨窗等需业务确认。

采集器和分析器分别版本化。App RPA、网页 RPA 和官方 API 都通过相同业务契约提交结果，但保留通道差异。不能只因底层模型名称相同，就认为几个入口的样本可直接混算。

### 4.2 分享链接与截图的定位

分享链接和截图增强客户复核能力，值得作为一等证据保存，并关联采样尝试、时间、原始回答和来源应用。它们不单独保证无法伪造或样本无选择偏差，也不代表其他厂商一定无法取得。

分别记录证据是否取得、链接是否仍有效以及文件权限。API 采样没有分享截图不自动表示采集失败；完整性要求按采样通道定义。分享地址可能公开或失效，应分别管理原始材料的授权访问与对客可展示材料。

### 4.3 来源对象去重，引用出现记录保留

建议分为四层：

1. **来源对象**：文章、视频、商品卡片等，可保留平台对象 ID、原始 URL、地址别名和规范化标识。
2. **引用出现记录**：某一次回答如何引用/展示某来源，包括原始地址、次序和类型。一个来源被引用十次，仍保留十条出现记录。
3. **抓取/补全尝试**：何时补取、跳转链、HTTP/业务状态、失败原因及可重试情况。
4. **内容快照**：某次取得的标题、正文或适用类型的信息及采集时间。同一 URL 更新后生成新快照。

不能为去重随意删除 URL 参数，也不能因为最终地址相同就假设所有来源对象等价。404 不删除过去的引用；后来补取的正文不能被默认为 AI 当时读到的正文；未查明原因前不把“平台缓存”写成事实。

信源引用率也需定义：按引用出现次数、含该来源的回答比例还是其他口径计算，按 URL、域名、内容类型或发布平台汇总，都会影响投放判断。被引用的第三方页面不自动成为我方内容资产；补全后引用或改写时应保留出处和资料使用范围。

## 5. 线索、内容、投放与经营事实

### 5.1 线索统一接入，来源和分配分别记录

候选链：`获客品牌/入口 → 原始触达事件 → 线索 → 分配历史 → 跟进 → 意向/商机 → 售前诊断 → 商业约定`。

- 官网表单、API 回调、人工和飞书导入使用一致接入能力，保留来源事件 ID 以防重复处理。
- 飞书是录入途径，小红书评论或抖音私信才可能是实际获客来源；两者分别记录。
- 同一联系人多次留资可关联，但保留每次触达和渠道。手机号相同不能无条件合并所有业务机会。
- 400 电话和活码记录触达时的实际路由与规则版本；不能用今天的销售路由重写历史归属。
- 已有有效归属的线索先核验并保留；无归属或冲突的进入相应处理队列。自动接入和自动分配是两种独立能力。
- 当前负责人、最初获客归属、协作参与和分成依据分别记录。转交销售不等于转走全部历史贡献。

### 5.2 内容生成纳入底座能力

候选链：`客户资料/品牌事实版本 + 薄弱问句与分析依据 → 内容任务 → 生成记录 → 文章版本 → 审核 → 投放`。

品牌事实及依据、客户资料、实体名称、受众、意图和场景由多个生成应用共同引用。生成记录保存模板/skill/模型与可知版本、输入资料、原始输出及操作人。规范的风格、事实约束和审核要求可以统一，各工具仍可尝试不同生成方法。

一篇文章可以回应多个问句；一个问句可以对应多篇文章。发布必须引用确定的文章版本，而不是一个随时会被改写的文档地址。客户要查看已发文章时，能从服务追溯到文章版本、平台、发布时间和 URL。

将能力纳入 BizBase，不等于先重写现有小组的全部代码。先核查已有生成和投放实现，能复用的适配统一数据与执行入口；缺失的追溯、权限和状态处理补在公共能力中。最终由多个界面调用同一套业务事实和规则，避免再出现两套独立发布台账。

### 5.3 投放必须闭合回执、回链与费用

候选链：`确定文章版本 → 投放订单明细 → 提交尝试 → 供应商回执 → 发布记录/URL → 链接核查 → 成本归属`。

- 一次订单可以有多个媒体明细、多个 URL 和部分成功结果；记录供应商订单号与回调标识。
- 请求超时先记“结果待确认”，查询供应商或对账。不能盲目重发导致重复发布或收费。
- 提交成功、平台受理、实际上线、取得回链、链接可访问、被 AI 引用分别记录；缺链和下架不能被总订单“成功”掩盖。
- 记录报价/价格快照、可选预算占用、实际费用、退款及对应服务/周期。一次支出跨多个服务时明确分摊，避免重复记全额。
- 自有官网和外部聚合平台可以共用发布事实，但各自的操作接口、成本类型和权限不同。

### 5.4 分成先有事实，再确定规则

先保留销售、运营在何时负责哪个服务，参与会议、诊断、内容、发布和交付的事实，以及合同、回款、发布费用和退款的可用记录。任务完成量不自动等于收入贡献，也不自动成为奖金依据。

未来分成计算应绑定规则版本、适用期间、人员任职区间、输入数据快照与确认状态。签约计提、回款计提、达标计提、利润计提或混合方式，均等业务决定。当前负责人不能直接覆盖历史销售或运营贡献。

## 6. 权限边界与候选能力接口

统一权限同时考虑用户、来源应用、服务范围、动作和有效时间。客户看板、渠道看板、销售、运营和后台采集/分析任务均纳入同一范围规则。

- 渠道可访问被明确授权的服务，不自动获得终端客户的全部历史与其他渠道数据。
- 公开信源的身份可以按规则复用，含客户问句、原始回答、私有附件和报告的关联不能默认跨客户共享。
- 同一来源同时被多个服务引用，其身份去重不意味着这些服务互相可见。
- 列表、详情、搜索、导出、分享材料及后台任务均需校验；只隐藏菜单不构成授权控制。

建议形成可由现有系统和新 AI 应用调用的业务能力：

| 能力 | 核心约束 |
| --- | --- |
| 接收线索、确认归属、转交跟进 | 防重复接入，保留来源与分配历史 |
| 建立/变更服务范围，换词，暂停/恢复 | 生效时间与确认依据可追溯，不覆写旧范围 |
| 维护实体、别名、比较集合 | 稳定身份与版本化解释规则 |
| 制定采样计划、提交观测与证据 | 计划与执行分开，通道差异保留 |
| 执行分析、发布指标和报告版本 | 固定输入与规则版本，可重算但不静默改历史 |
| 补全信源、生成内容、审核 | 来源快照和文章版本可追溯 |
| 提交投放、接收回执、确认回链与费用 | 幂等、部分成功、待确认及对账处理 |
| 记录贡献、核算候选分成 | 先事实后规则，金额与状态经确认 |

这些是业务动作候选，不等于只开放几组通用增删改查接口即可完成底座。执行所在的服务、存储方式与 Frappe App 边界在接口盘点后决定。

## 7. 建议落地顺序

1. **梳理并确定共享标识与规则。** 对照现有系统抽取一条真实业务链，明确组织/标的/服务/问句/实体/比较集合/任务之间的 ID 映射、维护方和授权范围。先确认 Top 和引用率等验收口径。
2. **打通一个真实客户的交付闭环。** 接入已有采集、分析、内容和投放工具，贯通服务范围、证据、文章版本、发布 URL；已知的单篇发布费用同时留存。验证换词、竞品更新和暂停能解释。
3. **统一获客与销售衔接。** 接入各渠道和人工入口，保留来源和已分配信息，连通意向、售前诊断、合同与启动；复用 CRM 的销售能力，补业务需要的公共接入约束。
4. **完善报告、成本与经营分析。** 将 Excel/JSON/HTML/看板变为同一组已定义数据的不同输出。根据完整费用与人员事实，再落实预算控制、分成及考核规则。
5. **开放标准接入给更多应用。** 提供契约、SDK/示例、沙箱和接入验证；避免所有人都必须采用同一界面，也避免新应用直接另起主数据。

顺序为建议，尚未排开发周期或决定现有系统替换。投放费用归属、审批和预算控制的深度，可按业务优先级分阶段实施，不要求先完成完整财务系统。

## 8. 用例验收与待确认规则

### 应覆盖的验收用例

- 渠道签约，服务两个终端客户；一个渠道用户只能看到获准服务。
- 同一联系人通过两种渠道留资，其中一次已经分配；不丢来源、不重复创建、不无故重分。
- 售前问句全集筛选为签约子集；报告说明基线范围变化。
- 年框服务中暂停，恢复时换问句、改竞品集合并升级分析模型；原报告可复查，新旧比较不混口径。
- 没有新增投放，只是增加了一个原回答中已有的竞品；系统能解释排名变化是否源于比较口径，不能自动认定服务效果恶化。
- 同一信源被十次回答引用，补取时 404；十次引用事实仍保留，补取状态可见。
- 一篇文章回应多个问句，投放两个媒体，其中一个超时后回调成功；不重扣费，所有回链能归属正确服务。
- 当前运营更换，历史文章和交付仍可追溯到当时参与人员，分成不被当前负责人覆盖。

### 后续逐项确认，不一次性要求全部作答

1. Top 的相对次序判定、并列、未提及、拒答、无品牌回答及可见度规则；三个聚合层级的分母与权重。
2. 监测任务的实际组成与“整体数据”的范围；排名比较集合是按标的、问句、任务还是其他范围配置。
3. 换词是一对一名额替换还是可以增减；竞品/别名更新的生效与合同验收方式。
4. 暂停影响哪些执行动作、配额、报告、验收、费用和到期日；年框的批次与周期规则。
5. 线索分配冲突优先级，活码和电话归属证据，销售转交与客户授权。
6. 信源引用率的统计单位与分母；内容风格、审核权限和发布验收标准。
7. 分成计提依据、考核节点、退款和费用分摊；是否需要预算上限及审批。

本轮只记录和建模，不自动接入外部平台、不发送或发布文章、不迁移客户数据、不变更生产权限。
