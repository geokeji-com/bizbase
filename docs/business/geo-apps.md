# GEO 四个业务应用

四个 Frappe App 安装在同一个 BizBase 站点。现有四个看板按角色展示和办理业务，业务 App 维护各自的权威记录。首批以现有两项客户服务验证业务链。以下结构是业务设计，不等于所有功能已上线。18080 本地预览已实现服务管理、任务执行与数据分析的首条业务链；内容管理暂保留工作区。各模块的现有功能与操作步骤见 [服务管理](../../apps/geo_service/README.md)、[任务执行](../../apps/task_execution/README.md)、[数据分析](../../apps/geo_analysis/README.md)。本版不包括真实平台 Worker、随机采样、自动模型排名或内容发布。

## 服务管理 · `geo_service`

定义为谁服务、服务什么、如何采样和考核。

| 数据对象 | 关键字段与约束 |
| --- | --- |
| GEO Service | ERPNext `Customer`、`Contract`、被服务组织、负责人、服务期、状态。签约方和被服务组织分别记录。 |
| GEO Service Member | 服务、人员、业务角色、生效期间。读取和操作按具体服务授权。 |
| GEO Service Target | 服务、优化标的类型、名称与资料版本。一项服务可包含多个标的。 |
| GEO Prompt | 原始问句，只去首尾空白后精确判重。文本创建后固定。 |
| GEO Service Prompt | 服务、标的、问句、监测起止时间、被替换问句、换词原因和确认依据。 |
| GEO Monitoring Plan / Revision | 服务、参与问句、执行能力版本及参数、频率、时区、时窗、间隔、分布和生效时间。历史任务保留原计划版本。 |
| GEO Sampling Slot | 计划版本、服务问句、平台条件、时窗、采用的任务与结果引用。同一任务可满足多个兼容的服务采样要求，每项服务独立计数。 |
| GEO Assessment Rule | 服务、标的、指标口径版本、阈值、考核范围与期间。允许配置多个指标条件。 |

**功能**　从合同建立服务，分配运营人员，维护客户资料版本和问句，换词，预览监测计划，生成应采记录并向任务执行提交需求，查看实际采集与缺口。服务暂停按 D-019 继续采集。

## 任务执行 · `task_execution`

这个 App 就是任务 Server。独立运行的 Worker 领取、续租和回传任务。Server 维护任务状态和结果，采集、发布和监测共用执行流程。

| 数据对象 | 关键字段与约束 |
| --- | --- |
| Execution Task | 类型、具体操作、输入版本、平台、端、能力版本、执行参数、时窗、优先级、状态、去重键，以及创建、首次领取、完成时间。未发生的时间留空。 |
| Execution Attempt | 任务、Worker、领取与结束时间、租约、实际账号及出口引用、错误分类。重试新增记录。 |
| Execution Result | 任务与尝试、结果结构版本、请求条件、实际观测条件、外部发生时间、Server 接收时间、结果和证据引用。 |
| Execution Capability | 操作、平台、端、版本、字段、默认值、可选值及组合规则。表单、派发和执行按同一版本校验。 |
| Execution Worker | 运行环境、能力版本、在线状态、最近心跳及并发。 |
| Execution Account / Proxy | 平台账号或网络出口、适用范围、健康状态、占用状态和凭据引用。明文凭据由受限凭据存储管理。 |

| 任务类型 | 常用产出 |
| --- | --- |
| 采集 | AI 回答原文、按原顺序记录的信源、可取得的截图和分享链接。区分无信源和未取得信源。 |
| 发布 | 平台回执、外部发布 ID、状态、回链。提交结果不明时先核对回执或外部状态。 |
| 监测 | 链接的 HTTP 状态及最终 URL、网页内容与时间，或关键词指数、地区、区间及数值。HTTP 404 可以是执行成功得到的观测结果。 |

**功能**　提交、领取、续租、回传、失败处理和结果查询。Server 记录 `creation`、`first_claimed_at`、`completed_at`。完成时间是 Server 确认终态的时间，实际采集或发布时间随结果单独记录。重复回传不增加有效样本，过期租约的回传不得覆盖已接收的结果。Worker 只取得执行所需的数据。采样条件与时窗都兼容时才能共用回答，授权通过各自的服务采样记录判断。

## 内容管理 · `geo_content`

定义要写什么、审核哪一版、在何处发布，以及投放的业务结果。

| 数据对象 | 关键字段与约束 |
| --- | --- |
| GEO Content Brief | 服务、标的、目标问句、选题、资料及分析依据。 |
| GEO Article / Revision | 稿件归属、标题、正文、版本、来源、作者和审稿状态。发布引用固定版本。 |
| GEO Content Review | 稿件版本、审核人、结论、时间与备注。 |
| GEO Placement | 稿件版本、服务归属、渠道、外部订单引用、计划时间、预算或报价、关联发布任务。 |
| GEO Publication | 投放记录、外部作品 ID、上线状态、发布时间、回链、实际费用及依据。外部回执可对应多个发布记录。 |

**功能**　登记选题、编辑稿件、审核、创建投放、提交发布任务、导入及核对回链与费用。发布任务记录执行过程，内容管理记录稿件是否已上线和实际投放结果。首版业务优先验证已有稿件及回链导入。

## 数据分析 · `geo_analysis`

把已获授权的原始样本变成可追溯的指标、分析和报告。

| 数据对象 | 关键字段与约束 |
| --- | --- |
| GEO Entity Set Revision | 优化标的、竞品及别名的版本。 |
| GEO Analysis Method Revision | 指标口径、样本过滤、分子分母、权重、模型或方法版本。 |
| GEO Sample Analysis | 服务采样记录、原始结果引用、方法版本、竞品版本、结果、解释与排除原因。重算追加记录。 |
| GEO Metric Summary | 服务、标的、问句、平台、期间、口径版本、应采和实采次数、有效样本、分子和分母。 |
| GEO Report Revision | 服务、期间、汇总依据、纳入的样本、报告解读、版本和交付状态。 |

**功能**　按服务采样记录读取原始证据，判定可见度与 Top 3，按问句或平台聚合，说明样本缺口并提供下钻。历史重算保留原有分析和报告。客户看板和文件分享使用明确授权的报告内容。

## 跨应用调用与首批验收

1. 服务管理引用 ERPNext 客户和合同，维护采样计划，向任务执行提交按时窗展开的需求。任务执行返回任务 ID。采集回传后，服务管理把符合计划的结果关联到对应的采样记录。
2. 内容管理提交确定稿件版本的发布请求，引用任务执行的回执更新投放状态。链接监测的结果也可从所对应的发布记录查看。
3. 数据分析按服务授权从采样记录追溯原始结果。四个看板通过同一组服务、任务、稿件和报告标识展示各角色所需的数据。原始共享回答不公开其他使用方。

首批业务验收依次打通一项真实服务的合同、问句、监测计划、采集任务与回答回传，再让第二项服务按自身计划走同一链路。用明确标记的测试数据验证两项服务的权限隔离和兼容时窗共享。数据分析先核对一次从 Top 3 结果到原文的追溯。内容管理先验证两项服务的稿件版本及回链归属，再联调发布。实际频次和考核口径以各服务的有效约定为准。
