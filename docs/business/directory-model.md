## 1. 对象

| 对象 | 标识/承载建议 | 定义及真实依据 | 首版处理 |
|---|---|---|---|
| 来源目录 | Directory Source；服务端配置 | 解释 ID 所属系统；S-01 的当前客户/对象 ID 与其旧系统 ID 不同 | 固定来源命名空间，不以名称推断相同客户 |
| 来源快照 | Directory Snapshot；私有不可变文件及清单 | S-01 来自 2026-11-02 实际导入，原对象映射文件共 61 条，有本次核验摘要 | 只截取批准的样本及必要关系；记录来源日期、提取日期、摘要、字段版本；不提交真实文件到 Git |
| 客户引用 | BB Customer Reference；新 DocType | 对应一个来源客户；S-01 登记客户与交付客户是两个不同 ID | 保存来源及客户 ID，用作授权锚点；名称为可重建展示资料，不成为另一份客户主档 |
| 优化对象目录项 | Directory Subject；只读返回结构 | S-01 对象明确归属其交付客户，保留对象及旧来源 ID | 从快照读取；首版不另建对象主表，不提供编辑 |
| 调用身份 | Frappe User；原生对象 | 当前本地除 Administrator、Guest 外，有一名启用 System User（U-01） | 人员登录与每个独立消费者的专用机器账号分别识别；首版隔离验收账号另建，不改 U-01 权限 |
| 客户读取授权 | User Permission + BB Directory Reader Role；原生对象 | 来源已有显式客户范围；目标例为测试读者获准读取 S-01 交付客户 | 尚无 BB Customer Reference 授权实例；复用原生记录结构，增加显式默认拒绝的业务判定 |

授权不是客户主数据的属性，数据来源也不是授权依据。来源合同、服务期、服务项、在服状态和客户层级均不能由目录关系推导。目录版本是文件版本，不是服务范围版本。

## 2. 关系与输出

- 一条客户引用由 `(source_system, source_customer_id)` 唯一确定；一个来源对象由 `(source_system, source_subject_id)` 确定，且在该来源的本次快照中归属一个客户引用。两种来源 ID 保留为字符串。
- 登记客户和交付客户分别授权，不沿上级、下级或签约关系继承。目录接口要求明确选择客户引用；客户端填写其他人员或应用标识不能改变当前认证身份。
- 首版授权粒度是客户目录：获准该客户后，可读该快照内已接入的全部对象的最小目录字段。它不授予该客户任何合同、服务、报告或文件访问权；需要对象级或服务级授权时另建明确规则，不沿用这一目录授权扩权。
- 首版只返回来源标识、客户/对象 ID、名称、来源分类（原值或未知）、目录版本、数据日期及 `snapshot` 模式。上级 ID、组织/税号、合同、成员、内部标记、旧优化身份、私有文件路径和凭证不进入响应。
- 目录项不是“全部正在服务的对象”。分类未知照实显示；首版仅对所接入快照中的完整样本负责。未来实时接入必须核验类型过滤、分页和权限，不以单页缺失推断删除。

## 3. 生命周期与授权规则

快照经校验后才能启用；重复摘要不重复导入；切换版本时一次性启用完整版本。无有效快照、摘要不符或读取失败返回不可用，不回退成空目录或静默读取其他版本。状态图和事件见[视图第 3 节](directory-model-views.md#3-生命周期)。

业务读取须同时满足：身份启用、具有启用的目录读取角色、存在指向本客户引用且适用此目录的显式授权、来源与快照有效。每次请求读取当前授权事实；已提交的撤权、角色撤销或账号停用在随后开始的请求生效，不承诺撤回已返回的数据或中断已在途请求。后续实时接入还须与上游当前许可范围取交集。

零授权不表示全部可见；Administrator 不作为目录日常用户或验收主体。普通目录账号没有客户引用的原生 read/select/export/share 权限；客户引用禁止分享，自定义业务入口执行同一判定。平台管理员仍属于受信任配置边界。

外部独立消费者首版使用专用机器账号，只代表该应用，不代表其最终使用者。需要替多人操作的应用须后续接入可验证的用户身份，不能提交任意 actor 参数代办。首版不开放客户/渠道外部访问，也不签发生产权限。

## 4. 唯一性与变更责任

客户引用内码由框架生成，外部关联继续使用来源复合身份；来源客户或对象改名不变身份，同名不自动合并。来源命名空间启用后不能随显示名称改动。人工修正真实资料回到来源系统；BizBase 首版仅由配置管理员导入经核验快照、维护引用和授权。

本地快照权限由本地验收配置明确授予，不继承历史来源权限；其使用范围限于隔离验收环境。原始快照、私有证据和测试凭证不进入镜像、Git 或可公开下载路由。原型模拟数据与真实快照分别管理。

## 5. 外部边界与复用

| 复用项 | 首版用途 | 自研缺口 |
|---|---|---|
| Frappe User、Role、User Permission、认证、标准配置页面 | 身份、基础角色、具体客户授权记录和配置 | 显式拒绝规则、禁止引用分享、跨入口一致性及请求审计 |
| 既有客户与对象来源 | 保留真实来源 ID 和关系，首版消费核验快照 | 白名单适配、版本标识、错误语义；实时接入另验 |
| 自研 BizBase App | 一个内部目录入口与同一受控接口 | 可重复安装、受 Git 管理的源码和隔离验收入口 |

审计只记录认证身份、受控入口、客户引用、目录版本、结果、时间及请求 ID；不记录密钥、原始载荷或客户端自称的操作者。复用 Integration Request 保存进入目录方法后的业务请求，User Permission 变更复用 Permission Log。读取成功须有持久审计；业务拒绝记录不能随异常回滚消失。框架在进入方法前拒绝的无效凭证请求依赖框架日志，不能声称已由此业务审计覆盖。

原生审计辅助函数会提交整个事务，因此首版明确只有业务读取；不能把这个事务方式用于未来业务写入。readback 和验收须确认日志保留期、访问权限、事务边界及存储失败处理，不承诺永久或不可篡改日志。

## 6. 目标与当前实现的差异

以下是实施前基线，逐项依据 E-07、E-09 的源码和本地只读检查；精确文件与行号在私有技术证据 `~/.codex/private/bizbase-org-audit-20261117/20261118-directory-boundary.md`。来源 schema 为当时工作树，不能冒充已部署版本。实施后的模型、入口和验收状态见[第 01 轮执行记录](../cycle/rounds/01/execution.md)。

| 项目 | 实施前事实 | 本次目标变化 |
|---|---|---|
| 客户与对象 | 来源存在稳定客户 ID、对象 ID、对象客户外键；BizBase 尚无自研 App | 新增客户引用和只读适配，保留已有关系；不修改来源 schema |
| 授权 | 原生 User Permission 零记录不是默认拒绝；来源服务凭证不等于人员权限 | 用显式角色及客户授权控制全部目录请求；不依赖原生宽松缺省 |
| 分享 | 原生 DocShare 可补充读取权 | 客户引用禁止分享；普通用户不能从原生资源接口绕开范围检查 |
| 数据版本 | 有真实历史映射文件；当前远端契约/凭证未验证 | 先发布明确标记日期的本地快照版；在线源失败不能伪装成已接通 |
| 审计 | 来源读取会计数和记日志，但日志失败并不阻断成功；普通框架请求不保证业务审计 | BizBase 接口补业务审计及失败路径验证 |
| 人员与应用 | 本地原生用户可用，SSO 与服务委托未完成验证 | 首版使用本地隔离身份；不先重建统一身份系统，不伪称跨系统 SSO 已完成 |
